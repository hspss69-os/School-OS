# ระบบงบประมาณโรงเรียน

ระบบใช้งานจริงสำหรับ Firebase `hspss-os` — ฐานข้อมูลใหม่ ไม่มีข้อมูลโครงการจากโรงเรียนต้นฉบับ

## เมนู

- ภาพรวม: งบจัดสรร ยอดใช้ไป และคงเหลือ แยกประเภทเงินและฝ่ายงาน
- โครงการและกิจกรรม: เพิ่มโครงการและกิจกรรม เลือกประเภทเงิน/ยอดตั้งต้น
- รายงาน: เลือกปี ฝ่าย โครงการ กิจกรรม และประเภทเงิน พิมพ์/PDF หรือส่งออก Excel
- อัปเดตงบประมาณ: ดาวน์โหลดแบบฟอร์ม Excel ตรวจสอบไฟล์ แล้วบันทึกข้อมูล

## การเข้าใช้งาน

ใช้ Google Sign-in บัญชีที่ได้รับอนุมัติใน `budget_access/{email ตัวพิมพ์เล็ก}` เท่านั้น เอกสารมี `active: true` และ `role` เป็น `admin`, `budget` หรือ `viewer`.

บัญชีผู้ดูแลเริ่มต้นกำหนดไว้ใน Firestore โดยไม่เผยแพร่รายชื่อหรือกุญแจส่วนตัวใน repository.

ผู้ดูแลและฝ่ายงบประมาณเพิ่ม/นำเข้าข้อมูลได้ ผู้ดูรายงานอ่านอย่างเดียว Browser แก้สิทธิ์ตัวเองไม่ได้ การเพิ่มบัญชีฝ่ายงบประมาณทำโดยเจ้าของโปรเจกต์ใน Firebase Console สร้างเอกสาร `budget_access/อีเมล` ระบุ `active: true`, `role: budget`.

## ข้อมูลทางการเงิน

- เก็บจำนวนเงินเป็นจำนวนเต็มหน่วยสตางค์ใน `budget_items` ป้องกันความคลาดเคลื่อนทศนิยม
- งบระดับโครงการและกิจกรรมแยกเอกสาร ไม่รวมยอดซ้ำ
- **ยอดใช้ไปมาจากไฟล์ที่นำเข้า** ระบบนี้ยังไม่มีหน้าบันทึกรายจ่ายหรือการยืมเงิน
- คงเหลือ = งบจัดสรร − ใช้ไป ไม่อนุญาตใช้ไปเกินงบจัดสรร
- เงิน 4 ประเภท: อุดหนุนรายหัว กิจกรรมพัฒนาผู้เรียน รายได้สถานศึกษา และอื่น ๆ

## Excel

ดาวน์โหลดแบบฟอร์มจากหน้าอัปเดตข้อมูลงบประมาณ หัวตาราง: รหัสโครงการ, ฝ่ายงาน, ชื่อโครงการ, ผู้รับผิดชอบ, กิจกรรม, ประเภทเงิน, งบจัดสรร, ใช้ไป.

1 แถวต่อโครงการ/กิจกรรม/ประเภทเงิน ชื่อกิจกรรมเว้นว่างหมายถึงงบระดับโครงการ ไม่ใช่ยอดรวมที่มีกิจกรรมรวมอยู่แล้ว

ไฟล์ใหม่อัปเดตรหัสโครงการที่ตรงกันเฉพาะปีที่เลือก รหัสอื่นยังอยู่ ไม่ลบกิจกรรมที่หายจากไฟล์โดยอัตโนมัติ แต่ละโครงการบันทึกเป็น transaction แยกกัน หากผิดพลาดอาจมีบางโครงการสำเร็จ ต้องตรวจสถานะก่อนนำเข้าใหม่ ตรวจ revision ก่อนเขียนเพื่อไม่ทับข้อมูลที่แก้พร้อมกัน

## การตั้งค่าหน้าตา

แก้ชื่อโรงเรียน ข้อความรอง สี และ URL โลโก้ที่ `school.config.js` ขณะนี้ใช้ชื่อกลางเพื่อรอชื่อและโลโก้ของโรงเรียนใหม่

## Firebase

- Project: `hspss-os`
- Firestore Standard Native `(default)`, `asia-southeast1`
- Authentication: Google
- Hosting: https://hspss-os.web.app
- `firebase.config.js` เป็น public web config ไม่มี service-account key

Deploy จาก root:

```sh
npx firebase-tools deploy --only hosting,firestore:rules --project hspss-os
```

ทดสอบ model:

```sh
node --test tests/*.test.cjs
```

การทดสอบ UI ใช้ข้อมูลจำลองใน service แยก ไม่บันทึกโครงการทดสอบลงฐานจริง กฎอ่าน/เขียนทดสอบด้วย Firebase Rules REST Test API ซึ่งจำลองคำขอ ไม่แก้ข้อมูลจริง

## ข้อจำกัดปัจจุบัน

ยังไม่มีการลบโครงการ/กิจกรรม ประวัติรายการจ่ายรายบรรทัด ระบบยืม เอกสารเบิกจ่าย หรือจัดซื้อจัดจ้าง ตามขอบเขต 4 เมนู ระบบรายงานเป็นยอดสรุปจากข้อมูลปัจจุบันที่นำเข้า ไม่ใช่รายงานธุรกรรมธนาคาร

## แผนจัดสรรที่ยังไม่มีข้อมูลใช้จ่าย

รองรับ `allocationKnown` และ `spendingKnown` ในรายการงบประมาณ เพื่อแยก “ไม่ระบุ” ออกจากศูนย์ จำนวนเงินภายในเป็นศูนย์สำหรับช่องที่ยังไม่ระบุ แต่การแสดงผลและรายงานต้องอ่าน flag ร่วมด้วยเสมอ กิจกรรมที่ยังไม่แยกวงเงินไม่เพิ่มยอดงบโครงการ ไม่กระจายยอดของโครงการให้กิจกรรมโดยเดาเอง

`budget_year_metadata/{year}` เก็บหมายเหตุและที่มาของข้อมูล อ่านได้เฉพาะสมาชิกที่ได้รับสิทธิ์ Browser เขียนไม่ได้ `budget_imports/{id}` เก็บหลักฐานการนำเข้าโดยผู้ดูแลโปรเจกต์ อ่านได้เฉพาะผู้ดูแลและฝ่ายงบประมาณ

กิจกรรมที่ใช้ชื่อผู้รับผิดชอบโครงการอ้างอิงจากแผน แสดงป้ายกำกับชัดเจน (`ownerInherited: true`) ไม่ถือว่าเอกสารได้แต่งตั้งผู้รับผิดชอบกิจกรรมนั้นแยกต่างหาก
